# ③ 流量与商品明细

## Goal

提供全店逐日流量和全店商品明细，并把订单数和交易额拆成推广直接成交和非推广两部分，用来判断推广有没有带动非推广成交。

父任务：`10-31-operating-data-gaps`。接口依据：
- `docs/research/traffic-cs-review-recon-2026-10-31.md` 第二、三节；
- `docs/research/goods-detail-plain-and-spider-font-2026-10-31.md`：明文商品明细接口、末点签名、推广直接成交字段。

术语见 `CONTEXT.md` 的 Non-Promo Sales。

## Requirements

### R1 全店流量

- R1.1 新增 `pdd diagnose traffic [--days 30]`。逐日数据（UV、浏览量、成交等）以及平台给出的同行均值、优秀值，取自明文接口 `queryMallFlowOverViewList`，原样透传。

### R2 数据来源（2026-10-31 实测后修订）

- R2.1 原来的前提"整个字形轮廓不变"经实测**不成立**，但"每个字形末点坐标稳定"成立。另外还发现明文接口 `queryGoodsDetailVOList` 可以直接返回全店商品明细。因此本期**不做字体解码**，商品明细直接走这个明文接口。末点签名方案只记录在研究文档里，作为后备。
- R2.2 如果明文接口下线或返回失败，命令返回错误或给出明确的 hint，不能把失败当作 0 来处理。

### R3 全店商品明细

- R3.1 新增 `pdd goods traffic [--days 1|7|30] [--goods-id <id>]`，默认 30。直接使用平台原生的区间口径（`queryType` 0/1/2），不把单日数据累加成区间。其他取值返回 exit 2。
- R3.2 每个商品输出：访客、浏览、收藏用户数、下单率、成交转化率、成交率、成交订单数、件数、买家数、交易额。上游只提供这些字段，不含退款字段。
- R3.3 推广拆分（用户决定按店透视的实现来做，见研究文档第 3 节）。推广数据来自稳定成本推广（`scenesMode` 1）和全店托管（3）两类计划，按 `goodsId` 归属：
  - 推广直接成交、间接成交的订单数和交易额分别输出；
  - `non_promo_*`（订单数、交易额）= 商品明细总量 − 推广直接成交；
  - 差值为负时置 null 并给出 hint，不截断为 0；
  - 访客数不拆分，推广点击数单独输出为 `promo_click_count`。
- R3.4 推广数据拉取失败时，所有推广相关字段和 `non_promo_*` 都为 null；拉取成功但该商品没有投放记录时为 0。这两种情况必须能区分开。
- R3.5 字段说明写明：`non_promo_*` 是用总量减去推广直接成交得到的差值，平台本身不提供这个拆分。推广字段的口径来自对第三方插件代码的静态分析，**还没有用有投放的店铺实测**。

## Acceptance Criteria

- [x] 前提验证结果已记录（见 R2.1 和研究文档）。
- [x] fixture 覆盖：有推广、无推广（输出 0）、推广拉取失败（输出 null）、差值为负（输出 null）、全店托管未开通（`adInfos: null`）、金额为纯数字（厘）和对象两种形态。
- [x] `goods traffic --days 14` 返回 exit 2。
- [x] 输出中没有自然 / 付费流量的访客拆分、加购率、跳失率字段，也没有 URL。
- [x] data 契约 v2 测试覆盖这两个命令。
- [x] README 写明：推广拆分的口径还没有经过有投放店铺的实测。
