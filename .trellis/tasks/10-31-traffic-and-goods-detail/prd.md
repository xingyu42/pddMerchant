# ③ 流量与商品明细

## Goal

提供全店逐日流量和全店商品明细，并把订单数和交易额拆成推广直接成交和非推广两部分，用来判断推广是否带动了非推广成交。

父任务：`10-31-operating-data-gaps`。接口依据：`docs/research/traffic-cs-review-recon-2026-10-31.md` 第一至三节。店透视插件的实现分析见 `tmp/recon/dts/codex-analysis.md`（不进 Git）。术语见 `CONTEXT.md` 中的 Obfuscated Metric 和 Non-Promo Sales。

## Requirements

### R1 全店流量

- R1.1 新增 `pdd diagnose traffic [--days 30]`。从 `queryMallFlowOverViewList`（明文）取逐日数据：UV、浏览量、成交等，以及平台给出的同行均值和优秀值，原样透传。

### R2 混淆字体解码（前置验证）

- R2.1 第一步先验证前提：同一店铺多次加载页面时，0-9 的字形轮廓保持不变，变的只是码位。前提不成立时，R3 退回只支持 `--goods-id`，单品数据走明文的 `queryGoodsStat` 接口，并同步更新本 PRD。
- R2.2 解码不引入新的运行时依赖。
- R2.3 解码结果要和明文来源交叉校验。校验不通过，或者数值里仍残留私有区字符时，相关值为 null，并给出 hint：平台字体混淆，数据不可用。
- R2.4 是否开启混淆取决于平台灰度。未开启混淆的店铺直接按明文解析。

### R3 全店商品明细

- R3.1 新增 `pdd goods traffic [--days 1|7|30] [--goods-id <id>]`，默认 30，直接使用平台原生的区间口径（`queryType` 0/1/2），不把单日数据累加成区间。其他取值返回 exit 2。
- R3.2 每个商品输出：访客、浏览、收藏用户数、下单率、支付转化率、支付订单数、交易额，以及上游提供的退款字段。
- R3.3 推广拆分。推广数据来自稳定成本推广和全店托管两类计划，按 `goodsId` 归属：
  - 推广直接成交、间接成交的订单数和交易额分别输出；
  - `non_promo_*`（订单数、交易额）= 商品明细总量 − 推广直接成交；
  - 差值为负时置 null 并给出 hint，不截断为 0；
  - 访客数不拆分，推广点击数单独输出为 `promo_click_count`。
- R3.4 推广数据拉取失败时，所有推广相关字段和 `non_promo_*` 都为 null；拉取成功但没有该商品的投放记录时为 0。两种情况必须能区分开。
- R3.5 字段说明写明：`non_promo_*` 是用总量减推广直接成交得到的差值，平台本身不提供这个拆分。

## Acceptance Criteria

- [ ] R2.1 的前提验证结果已经记录在本任务里，结论为成立或不成立。
- [ ] 解码使用的 fixture 至少包含两次加载、映射不同的样本，两次都能解出相同的数值。
- [ ] 交叉校验失败时，fixture 中对应的值输出 null 并带 hint。
- [ ] fixture 覆盖：有推广、无推广（输出 0）、推广拉取失败（输出 null）、差值为负（输出 null）。
- [ ] `goods traffic --days 14` 返回 exit 2。
- [ ] 输出中没有自然流量 / 付费流量访客拆分、加购率、跳失率字段。
- [ ] data 契约 v2 测试覆盖这两个命令。
