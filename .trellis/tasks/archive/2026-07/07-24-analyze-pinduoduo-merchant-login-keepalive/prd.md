# 分析 pinduoduo 商家工作台登录保活原理

## Goal

基于 `pinduoduo/` 中的商家工作台程序文件进行只读静态分析，解释商家登录状态如何建立、持久化、续期、检测失效与恢复，并给出可复核的证据边界。

## Requirements

- 分析范围仅限商家工作台，不把消费者端登录状态混入结论。
- 从启动入口、认证相关模块、网络请求、定时任务、本地文件或数据库、日志与配置中寻找证据。
- 区分“保存登录状态”“业务心跳”“令牌刷新”“掉线检测”“自动重登”等不同机制，避免把普通轮询都称为保活。
- 不运行未知可执行文件，不修改 `pinduoduo/` 内容，不提交其中可能包含的账号、Cookie、令牌或设备标识。
- 结论按“已确认 / 高可信推断 / 尚未确认”分级，并提供文件、符号、字符串或调用关系作为依据。

## Acceptance Criteria

- [x] 给出从程序启动到已登录工作态的完整链路图或分步说明。
- [x] 说明登录凭据的主要载体及其本地持久化位置或模块。
- [x] 说明保活触发方式、周期或触发条件，以及对应网络接口或消息通道。
- [x] 说明失效判定和恢复行为，包括是否自动刷新、自动重登或要求用户重新登录。
- [x] 标注证据强度与剩余盲区，避免把字符串命中直接当成真实调用链。
- [x] 全程保持只读静态分析，不执行 `PddWorkbench.exe` 或目录内其他未知程序。

## Out Of Scope

- 修改当前 `pdd-cli` 的登录、认证或保活实现。
- 绕过验证码、风控或服务端认证控制。
- 对真实账号进行在线登录、抓包或生产环境验证。
