# 技术债务清理

## Goal

系统性清理 pddMerchant 项目中已识别的 5 项技术债务，提升商品发布流程的功能完整性、可维护性和扩展性。

## Requirements

### 功能需求

1. **多 SKU 规格填充** (P0 - High Priority)
   - 支持多 SKU 商品的规格表单自动填充
   - 处理 SKU 组合表格（颜色 × 尺码 → 价格矩阵）
   - 基于 `source.skuText` 解析结果填充

2. **商品详情图上传** (P1)
   - 实现商品详情图自动上传功能
   - 处理图片顺序和尺寸校验
   - 确保详情页图片正确展示

3. **商品属性映射** (P1)
   - 实现 `source.properties` 到平台属性的映射
   - 处理必填属性和可选属性
   - 减少平台校验错误

4. **满件折扣配置抽象** (P2)
   - 将硬编码的 9.5 折抽象为可配置项
   - 支持环境变量或配置文件控制
   - 保持向后兼容性

5. **Phase 2 废弃模块清理** (P2)
   - 移除已删除模块的测试引用
   - 清理废弃的 fixture 文件
   - 更新相关文档

### 非功能需求

- **架构合规**: 严格遵守分层依赖 `commands/ → services/ → adapter/ → infra/`
- **测试覆盖**: 新增功能单元测试覆盖率 ≥ 80%，E2E 测试必须通过
- **Mock 模式**: 所有新增功能支持 `PDD_TEST_ADAPTER=fixture` Mock 模式
- **代码质量**: 函数 < 50 行，嵌套 ≤ 3 层，无单字母变量
- **日志脱敏**: 通过 `src/infra/logger.js` 记录日志，敏感字段自动脱敏
- **错误处理**: 使用 `PddCliError` 并映射到 8 种退出码

### 约束条件

- 纯 ESM，不引入 TypeScript 或 CommonJS
- 除非必要，不新增外部依赖
- Envelope 合约 `{ ok, command, data, error, meta }` 不可变，仅 `meta.warnings` 可扩展

## Notes

### 子任务列表

| 子任务 Slug | 优先级 | 影响范围 | 风险等级 |
|-------------|--------|----------|----------|
| `multi-sku-fill` | P0 | 商品发布核心流程 | High |
| `detail-images-upload` | P1 | 商品详情页展示 | Medium |
| `property-mapping` | P1 | 平台校验合规 | Medium |
| `discount-config-abstract` | P2 | 促销策略灵活性 | Low |
| `phase2-cleanup` | P2 | 代码库健康度 | Low |

### 执行策略

- **并行执行**: 5 个子任务相互独立，可并行开发
- **优先级排序**: 建议按 P0 → P1 → P2 顺序完成
- **无硬依赖**: 任一子任务失败不阻塞其他任务

### 共享资源冲突策略

可能同时修改的文件：
- `src/adapter/goods-publish/form-filler.js` — 多个子任务共同修改
- `test/goods-publish.unit.test.js` — 所有子任务可能新增测试
- `docs/architecture-overview.md` — 最终统一更新

**冲突处理**:
- 每个子任务完成后立即在 handoff 文档记录改动范围
- 最后一个完成的子任务负责合并文档更新
- 如有代码冲突，由父任务在 Phase 3 统一协调

### 父任务职责

父任务仅负责统筹协调、交叉验收和最终文档更新，不承担直接实现工作。实现工作全部由 5 个子任务完成。
