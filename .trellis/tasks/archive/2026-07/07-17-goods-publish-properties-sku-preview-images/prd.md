# 补齐商品属性与 SKU 预览图

## Goal

补齐 `goods publish --url` 草稿中的商品属性和 SKU 预览图，使源商品 `447841256386` 创建的商家草稿不再出现属性区域空缺、颜色规格行无预览图，同时保持默认只保存草稿和失败关闭边界。

## Confirmed Evidence

### 已有草稿与缺陷

- 2026-07-17 已成功创建并只读核对草稿 `goods_id=978682033971`、`goods_commit_id=196279140280`；标题、轮播图、详情图、运费模板、18 个 SKU、价格和库存正确。
- 用户截图确认该草稿的颜色规格行已经选择“灰色”，但规格预览图上传位为空。
- 上一任务明确没有实现商品属性填充，也没有把 SKU/颜色图片写入规格行；本任务是该真实草稿验收的直接后续。

### 源商品证据

- 调查数据中的 `goodsProperty` 含 20 组结构化属性；18 个 SKU 均带 `thumbUrl`。灰色套装、蓝色套装、米黄色套装各有且仅有一张颜色图，同色 6 个尺码复用同一张图，且三张图分别能在轮播图中找到一致证据。

### 商家模板与 DOM 证据

- 2026-07-18 对既有草稿进行无保存复核：普通 DOM/HTML 中不存在 `is_important` 或 `isImportant` 属性/变量；`GET /draco-ms/mms/template/mall` 的 JSON 响应才包含 `required` 与 `is_important`。当前响应中 19 个属性对象带 `is_important`，其中 5 个为 `true`。
- 同日在用户已打开的真实 Chrome 商家后台标签页再次只读确认（未点击、未刷新、未保存）：HTML 字符串、DOM attributes、DOM element properties 与 `window` 上的 `is_important`/`isImportant` 命中均为 0；DOM 仅有 5 个 `<span>重要</span>` 显示标签，分别属于面料俗称、件数、袖长、下装长和安全等级。
- 真实 Chrome Resource Timing 进一步确认：商品编辑页与属性模板请求同源于 `https://mms.pinduoduo.com`，由官方页面以 `fetch` 发起，路径为 `/draco-ms/mms/template/mall`，携带 `catId`、`goodsCommitId`、`goodsId`，现场响应状态为 200。它属于官方商家后台内部接口；未在拼多多开放平台官方检索中找到该路径，不能视为对外公开、承诺稳定的 Open API。
- 目标类目的属性具有动态依赖：使用 Playwright 的真实指针点击选择 `面料俗称=棉` 后，`材质=棉` 与必填 `成分含量=50%（含）-70%（不含）` 会在同一页面自动出现；脚本式 `element.click()` 只改变可见选择，不会触发这条依赖链。初始模板响应不含这两个动态模型，选择后也没有第二个模板响应，但新行当前的 React 表单模型包含完整平台 ID、必填标记和候选值。
- 规格图区实际存在 3 个已选颜色容器（灰色、蓝色、黄色）和 1 个空白新增行，每个颜色容器各有一个图片上传控件；目标不是给 18 个 SKU 表格行重复上传 18 次。
- 选择尺码规格后页面会自动启用尺码表；现场确认它会阻塞最终上架。官方停用入口是 `data-tracking-click-viewid="disable_size_chart"`，点击后还需确认“确认停用”；成功后停用入口和尺码表同时消失。停用前后 payload 没有可安全硬编码的布尔开关，`size_spec_id` 甚至从一个非零 ID 切换到另一个非零 ID。

### 规划约束

- 旧规划 `07-10-property-mapping` 建议模糊匹配和仅告警继续保存，尚未结合当前结构化源数据、严格保存请求校验和真实草稿证据；本任务不得直接照搬其猜测性策略。

## Requirements

### R1 源数据契约

- 从现有调查数据和实时源投影中确认并保留结构化商品属性，以及可与规格值或 SKU 组合唯一关联的图片字段。
- 不得把详情文本、轮播图顺序或 SKU 数组索引当作属性值/规格图的猜测来源。
- 源属性或规格图证据不完整时必须返回稳定问题码或明确降级结果，不得静默伪造。

### R2 商品属性映射与填写

- 商家类目确认后，从属性模板接口读取平台标识、`required`、`is_important`、输入类型和候选值，并按模板响应分级：`required=true` 为平台必填，`is_important=true` 为影响填写率的重要属性，两者均为 false 才是可选属性。
- 不得尝试从 DOM 读取 `is_important` 变量，也不得仅凭页面“重要”文字建立机器契约；模板响应缺失或字段冲突时必须失败关闭并记录稳定问题。
- 使用该内部模板接口时必须校验响应来源、状态和字段结构；接口路径或结构漂移时不得用旧字段位置、DOM 顺序或默认属性列表继续保存草稿。
- 平台必填属性缺失必须在保存前失败；重要属性作为本任务的草稿质量门槛也要求完整、唯一匹配，但错误中必须明确它是“重要属性未完成”，不能伪报为平台必填错误。
- 源属性只能通过平台标识或唯一规范化名称/候选值匹配；禁止模糊命中多个候选后盲选。
- 可选属性有唯一映射证据时正常填写；无法唯一映射时跳过并记录 `property_mapping_partial` 告警，不阻止草稿保存，也不得选择近似候选或默认值。
- `面料/材质=棉/棉` 到商家 `面料俗称=棉` 之类的平台字段差异，只能使用本任务明确记录并有唯一候选证明的窄化别名/值归一化，不能扩展成通用模糊匹配。
- `面料/材质` 只可在当前模板分别唯一存在 `面料俗称`、`材质` 且候选值唯一时映射到这两个目标；不同分类仍以实时模板为准，禁止硬编码完整属性清单。
- 初始属性填完后必须在同一页面有界读取刚出现的新属性行模型，只补写新增模板属性，并循环到稳定（最多 5 轮）；不得先保存阶段草稿或重载页面。最终只保存一次，并按合并后的完整计划校验，包括动态出现的 `成分含量`。
- 不把颜色、尺码等 SKU 维度重复写成普通商品属性，除非平台类目确实要求且存在唯一映射证据。

### R3 SKU 预览图映射与上传

- 源图片必须按规格值或完整 SKU 组合映射到对应商家规格行/规格值上传控件。
- 相同颜色的多个尺码可以复用同一张已证明属于该颜色的图片；不同颜色不得因为数组顺序而互相串图。
- 对目标商品，将源规格值 `灰色套装`、`蓝色套装`、`米黄色套装` 分别映射到商家标准颜色 `灰色`、`蓝色`、`黄色`，每个已选颜色容器只上传一次；空白新增颜色行必须忽略。
- 上传必须等待每张图片独立的成功响应并读回页面状态；缺失、非唯一映射或上传失败不得被误报为完成。

### R4 保存与发布安全

- 保存请求放行前验证商品属性和 SKU 预览图满足本任务确定的必填策略，并继续验证标题、图片、模板、SKU、价格和库存。
- 动态属性稳定后、唯一一次最终保存前，必须通过官方两步交互停用活动尺码表，并以停用入口和尺码表都消失作为读回证据；控件漂移、确认缺失或读回失败时停止保存。没有活动尺码表时允许无操作继续。
- 默认仍只保存草稿；本任务验证不得携带 `--confirm`，不得自动提交发布或删除既有草稿。
- 日志、错误和测试产物不得输出原始图片 URL、Cookie、代理数据或完整平台响应。

## Out of Scope

- 标题改写、详情装修增强、满件折扣和正式提交发布优化。
- 为属性或规格图引入无法由源数据/平台候选值证明的人工猜测规则。

## Acceptance Criteria

- [x] 源投影包含目标商品的结构化属性和可唯一映射的 SKU/颜色图片证据；缺失证据可被确定性测试捕获。
- [x] 属性映射覆盖目标类目的真实必填/重要属性（包括面料俗称、件数、袖长、下装长、安全等级等），非唯一/无候选映射失败关闭，不盲选。
- [x] 动态依赖属性由真实指针点击在同页触发并补齐，整个流程只保存一次；最终草稿独立读回包含 `材质` 与 `成分含量`。
- [x] 可选属性能唯一匹配时填写；不能唯一匹配时跳过并仅产生 `property_mapping_partial`，不选择近似值，也不阻止其他验收项完整的草稿保存。
- [x] 灰色、蓝色、黄色三个已选颜色规格各上传并读回正确预览图；空白新增行无上传，18 个 SKU 不因尺码重复而发生串图。
- [x] 保存请求体或页面状态校验能捕获属性缺失和 SKU 预览图缺失。
- [x] 尺码表在最终保存前自动停用；缺少官方确认或停用读回不一致时不保存，真实草稿重新打开后不存在停用入口和尺码表。
- [x] Fixture/unit 测试覆盖属性输入类型、候选匹配、必填缺失、颜色图片复用、非唯一映射和上传失败。

- [x] 相关定向测试、PBT/fixture 回归和受影响共享测试通过，`--json` 单行 envelope 与日志脱敏契约不变。
