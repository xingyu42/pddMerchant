# 青果短效代理接入源商品抓取

## Goal

为 `goods publish --url` 的消费者端源商品抓取增加可选的青果短效 HTTP 代理，使当前出口遭遇 H5 空壳墙或价格脱敏时，可以在严格边界内更换出口完成抓取，同时不改变商家端流量、其他 CLI 命令或现有直连默认行为。

## Background

- 当前发布流程先通过消费者端 `mobile.yangkeduo.com` 抓取源商品，再进入类目解析、标题处理、商家后台草稿填写与保存。
- 当前网络出口实测会得到 React 未 hydrate 的“打开 APP”空壳页；消费者登录态能改善部分价格脱敏，但不能稳定解除空壳墙。
- 青果按量提取接口返回短效代理地址、地区、运营商和截止时间；提取接口的 `key` 参数在青果侧命名为 `AuthKey`，代理节点账号/密码鉴权为可选能力，首版不启用。
- 项目已有软风控冷却、会话健康和熔断机制；代理重试必须与这些机制协调，不能形成无限轮换。

## Requirements

- 代理能力仅作用于消费者端 Source Product Fetch，不代理商家后台草稿、表单填写、保存、提交或其他命令。
- 默认保持现有直连行为；仅当 `PDD_SOURCE_PROXY_PROVIDER=qingguo` 时启用代理。
- 启用后采用失败关闭：代理配置、提取或连接失败不得自动退回直连。
- 敏感配置仅从环境变量读取：`PDD_QINGGUO_AUTH_KEY`。
- 首版仅支持无节点账号/密码鉴权的 HTTP 代理，不增加 SOCKS5、命令行凭据参数、地区或运营商配置。
- 青果提取固定使用随机地区、随机运营商、`num=1`、`distinct=true`。
- 每次抓取尝试即时提取一个代理；剩余有效期不足 30 秒时视为不可用。
- 一个代理只服务一个全新的消费者浏览器上下文，不跨尝试或商品复用。
- 每个上下文只读加载共享消费者登录态，不将代理会话状态写回登录态文件。
- 仅代理基础设施失败时最多重试 2 次，即单次源抓取最多使用 3 个代理；账号降级及其他不可重试错误只使用首次尝试。
- 可重试情况仅限代理临时提取/连接故障和代理提前失效。
- 不可重试情况：价格或 SKU 缺失、PDD H5 空壳墙、验证码、滑块、明确风控弹窗、消费者登录失效、青果认证/权限/余额/额度错误、非临时程序错误。
- 价格或 SKU 首次缺失即确认消费者账号降级：立即停止、不再换代理重试、永久删除当前消费者登录态，且不写入全局软封冷却。恢复必须使用其他消费者账号重新登录。
- 新消费者账号登录成功后清除旧的源抓取冷却状态，允许立即进行一次抓取。
- 青果单次提取超时 10 秒；两次重试前的基础设施退避分别为 500ms、1000ms；所有等待服从现有命令总超时和中断信号。
- 不执行第三方出口 IP 预检，也不新增独立代理诊断命令。
- 重试后成功时，命令保持成功并在 `meta.warnings` 增加 `source_proxy_retry_recovered`。
- `goods.publish` 命令层必须把 service 返回的 warnings 送入 runner 的保留 `warnings` 通道，确保代理恢复警告以及现有发布警告进入 `meta.warnings`，而不是只留在 `data` 中。
- 普通 JSON 输出不得包含代理地址、端口、AuthKey 或青果原始响应。
- `--verbose` stderr 只允许记录脱敏诊断摘要，例如供应商、尝试序号、地区、运营商、剩余有效期、结果分类和脱敏 request ID。
- 青果适配逻辑放入独立、供应商专用的 adapter 模块；不建设多供应商插件或注册框架。
- 使用项目现有 `PddCliError`、`ExitCodes` 和 envelope 契约映射代理配置、认证、额度、限频、不可用和网络错误。
- `pdd doctor` 仅检查商家端与消费者端登录态是否在线，不扩展为代理、商品页渲染、价格/SKU 可见性或源抓取健康检查。
- 默认不新增自动测试；只有实现中发现缺陷或现有测试因行为变化需要适配时才补测试。

## Error Semantics

- 配置不完整：`E_USAGE`。
- AuthKey、HTTP 401/403/407 或权限错误：`E_PROXY_AUTH` / `ExitCodes.AUTH`。
- 余额不足或提取额度耗尽：`E_PROXY_QUOTA` / `ExitCodes.BUSINESS`。
- 青果接口限频：`E_PROXY_RATE_LIMIT` / `ExitCodes.RATE_LIMIT`。
- 临时资源不足或提取失败：`E_PROXY_UNAVAILABLE` / `ExitCodes.NETWORK`。
- 代理连接超时、拒绝或提前断开：`E_PROXY_NETWORK` / `ExitCodes.NETWORK`。
- 空壳墙保留现有 `E_RATE_LIMIT` 并立即停止；价格或 SKU 缺失保留 `E_RISK_CONTROL_SOFT`，删除消费者登录态后立即停止。
- 消费者登录态删除失败：`E_AUTH_STATE_DELETE_FAILED` / `ExitCodes.AUTH`，保持失败关闭。

## Acceptance Criteria

- [x] 不配置代理环境变量时，源抓取继续使用现有直连路径，行为不变。
- [x] 配置青果后，只有消费者端源商品抓取使用代理，商家端及其他命令保持直连。
- [x] 代理启用但配置不完整、提取失败或连接失败时，不发生直连回退。
- [x] 每次尝试使用新的代理和新的消费者上下文，并且不写回消费者登录态。
- [x] 仅代理基础设施故障最多重试 2 次；价格或 SKU 首次缺失立即停止。
- [x] 账号降级后永久删除当前消费者登录态，不更新全局软封冷却；新账号重新登录后可立即进行一次抓取。
- [x] `pdd doctor` 保持登录在线检查边界，不承担真实源抓取环境诊断。
- [x] 重试恢复成功时 `meta.warnings` 包含 `source_proxy_retry_recovered`。
- [x] `goods.publish` 的现有发布 warnings 不因命令层接线调整而丢失，并由 runner 合并进 `meta.warnings`。
- [x] stdout envelope 结构保持 `{ ok, command, data, error, meta }`，JSON 模式保持单行纯净输出。
- [x] 日志和错误中不出现 AuthKey、完整提取 URL、完整代理节点或青果原始响应。
- [ ] 至少一次真实商品草稿模式通过青果代理完成源抓取并继续后续发布流程。
- [x] 运行相关现有测试和 `npm test` 无回归；不强制新增测试。

## Out of Scope

- 多代理供应商框架或自动供应商切换。
- SOCKS5、地区筛选、运营商筛选、代理池预取或跨商品复用。
- 商家端代理、全局浏览器代理或其他命令代理。
- 第三方出口 IP 检测及独立代理诊断命令。
- 验证码、滑块、明确风控挑战的自动绕过。
