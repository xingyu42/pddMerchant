# 上货抓取商品数据缓存

## Goal

为 `pdd goods publish --url` 的源商品抓取结果增加本地临时缓存。一次上货在抓取成功但后续步骤失败时，相同 `goods_id` 重试应复用已抓取数据；上货成功后立即清理该商品的临时缓存，减少重复页面访问、青果代理消耗和风控失败。

## Background

- 当前命令会先从 URL 提取稳定的 `goods_id`，随后每次都创建消费者浏览器 Context 抓取 `mobile.yangkeduo.com`。
- 真实抓取可能受消费者登录态、抓取冷却、页面风控和青果代理可用性影响。
- 抓取成功后得到上货需要的标题、类目、价格、轮播图、规格文本、属性和详情图等字段；仓库当前没有源商品持久缓存。
- `tmp/` 已被 `.gitignore` 排除；缓存放在其独立子目录中，不得提交到仓库，也不得包含 Cookie、AuthKey、代理节点或其他认证数据。

## Requirements

- R1：缓存按解析后的 `goods_id` 隔离；同一商品的链接和纯数字 ID 必须命中同一份缓存。
- R2：只有成功抓取且通过现有源商品校验的数据才能写入缓存，失败页、风控页和不完整数据不得缓存。
- R3：存在有效缓存时直接复用，不创建消费者浏览器 Context、不获取青果代理、不发起源商品页面请求，也不受源抓取冷却状态阻塞。
- R4：缓存只保存后续上货实际需要的源商品字段，不保存抓取诊断字段、登录态、代理配置或凭据。
- R5：缓存文件缺失、损坏、版本不兼容或校验失败时视为未命中，继续走现有实时抓取流程；成功后用原子写入覆盖缓存。
- R6：缓存读写失败不能破坏一次本来可以成功的实时上货；通过现有 logger 记录不含敏感商品数据的诊断信息。
- R7：fixture 模式保持确定性，不读取或写入真实本地缓存。
- R8：缓存必须放在仓库 `tmp/goods-publish-source-cache/` 独立目录；抓取成功后写入，后续类目、表单、草稿或提交步骤失败时保留，供下一次重试使用。
- R9：本次命令成功完成时删除当前 `goods_id` 的缓存。默认草稿模式以草稿保存成功为完成；带 `--confirm` 时以提交成功为完成。
- R10：成功后的清理失败不得把已经成功的上货改报为失败，也不得触发重复提交；应记录脱敏警告并保留原成功结果。

## Acceptance Criteria

- [x] AC1：首次真实抓取成功后在 `tmp/goods-publish-source-cache/` 产生该 `goods_id` 的临时缓存。
- [x] AC2：再次上货同一 `goods_id` 时读取缓存，源抓取函数、消费者 Context 和代理获取均不执行。
- [x] AC3：缓存命中时，即使抓取冷却处于生效状态，也能继续使用缓存完成后续上货流程。
- [x] AC4：损坏或不完整缓存会安全回退到实时抓取，并在成功后修复缓存。
- [x] AC5：抓取失败不会产生可被后续误用的缓存；写缓存失败不会把本次成功抓取变成上货失败。
- [x] AC6：缓存内容不含 Cookie、AuthKey、代理地址、请求 ID 和以下划线开头的抓取诊断字段。
- [x] AC7：相关 goods-publish 单元测试通过；fixture 命令契约与单行 JSON 输出保持不变。
- [x] AC8：类目、表单、保存草稿或提交失败后缓存仍存在，下一次相同商品重试能够命中。
- [x] AC9：草稿模式保存成功后缓存被删除；`--confirm` 模式提交成功后缓存被删除。
- [x] AC10：缓存删除失败时命令仍返回真实的上货成功结果，并给出清理警告。

## Out of Scope

- 不缓存运费模板查询、类目解析结果、商家草稿或提交结果。
- 不下载并缓存图片二进制文件；仅复用源数据中已有的图片 URL。
- 不新增共享服务或远程缓存。
- 不做长期缓存、自动过期、后台清理、容量淘汰或 `--refresh-source` 命令选项；需要强制重抓时可手动删除对应临时文件。
