# 技术设计

## 阶段 0：只读核验

新增独立诊断脚本，不注册为 pdd 正常认证命令，不接入现有调用方。显式要求专用测试文件；不读取默认账号目录或注册表。用受控隔离上下文加载材料，仅选择 checkLogin URL 适用的 Cookie；上下文不导航，不混入其他账号。

独立 Node HTTPS 请求显式发送冻结的 Cookie 头，不使用浏览器 request API 或共享 CookieJar。固定 GET https://mms.pinduoduo.com/janus/api/checkLogin，证书校验开启，不跟随重定向，15 秒超时及 1 MiB 正文上限。暂时网络错误最多重试一次，500 毫秒退避；取消及总期限限制整个核验。只返回固定原因、HTTP 状态、UTC 时间和验证状态。

诊断脚本检查当前候选和仅移除 PASS_ID 的独立对照候选；对照候选不得成为业务材料。即使 GET 两种结果符合预期，完整迁移门仍为 pending，直到固定可信店铺来源、只读访问和异常场景证据核验完成。离线单元测试不构成真实协议通过的证据。

## 阶段 1：候选与验证

通过阶段 0 后将已确认协议封装在站点 adapter。冻结状态生成按固定目标 URL 的 Cookie 头，规范化 token 仅在内存中存在。可信身份响应通过专用 normalizer 转为 mallId/displayName，不复用当前 URL/Cookie/storage/通用 XHR 搜索兜底作为认证证明。

候选检查返回 { verdict, reason, checked_at, http_status }。服务层编排身份核对及只读店铺验证；异常映射 PddCliError，网络无法判定使用 NETWORK 退出码，明确失效使用 AUTH。

## 阶段 2：提交

同一文件保存 cookies、origins 及 versioned merchant auth 元数据。浏览器只接收标准状态字段。原子替换只能使用已验证候选，不允许再次读取活动上下文。已知账号或规范化文件路径串行；首次登记锁协调账号锁。锁不能仅因年龄抢占存活的长任务，提交再次检查锁、版本、截止时间及取消。

保留注册账号 slug；新账号先落盘后发布注册，失败清理未发布文件。网络无法判定与旧材料明确拒绝只更新相应检查状态，不用失败候选覆盖旧 Cookie。

## 阶段 3：调用方

统一商家登录、init/account add、runner、doctor、后台检查及成功命令回写。store identity 绑定检查前置；跨店铺状态不写回原账号。成功业务回写失败用稳定 warning 表达。后台仅检查同步，不保证服务端续期。单行 JSON 和秘密保护统一保持。

## 切换与回退

在可信身份协议未确认前不更新现有 POST 规范，不启用 GET 作为生产认证。切换前停止旧后台，离线测试和真实专用账号只读验收全部通过后启动新版后台。失败停止发布，不自动恢复旧凭据。

## 收敛决定

2026-10-05：取消认证后台路线。移除 daemon 入口、进程管理、认证 refresher、fixture 刷新及专用路径/日志/计时配置，清除 single/batch/login 自动启动、doctor 后台状态。旧本地配置仅忽略 refreshIntervalMs/refreshJitterMs，其他未知键仍严格校验；公开配置不再接受这两键，环境变量不再映射，配置编辑 restartRequired 保持 false。只读验收脚本改为真实登录和命令检查/回写，不再调用后台。此前关于后台实现/启动的设计属于历史记录，以此调整为准。

真实固定 GET 及店铺只读协议已验证；直接写入只允许本次进程内经验证的冻结候选，JSON/外部对象不能伪装验证品牌。内部不附加不必要的派生 login_token 字段，不导出、不重复持久化 token/ck。不使用 SDK、扩展或日常浏览器。输入身份与候选身份必须一致，原注册 slug 固定。登记与后台/命令事务用锁和版本协调；存活进程不能因年龄被抢占，锁恢复不能覆盖新所有者。

显式业务店铺与认证绑定不同即跳过回写，即使身份接口仍返回主体店铺；观察页面状态只可限制写入，不能充当认证证明。新版验收脚本临时保存自身隔离材料并验证登录、命令检查及安全回写，随后删除；不修改原账号，后台已移除。2026-10-05 已完成真实扫码验收，退出码 0、无 warnings，临时材料清理成功；验收范围为 shop_read 和认证保存流程，非所有业务权限。

商家登记全程与 remove/default/rekey/upsert 使用同一注册表锁，内部 upsert 必须验证并复用本次锁 token，不能另建登记锁形成竞争或重入死锁。普通账号变更有界等待 10 秒，超时返回 E_LOCK_TIMEOUT；不会为了并发可用性抢占扫码任务。已有账号候选已经验证后，注册信息更新失败仍报失败，保留已验证材料而不恢复未经重新检查的旧材料；新账号发布失败则清理未发布材料。
