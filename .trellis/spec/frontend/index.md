# Frontend Development Guidelines

The only frontend is the daemon console under `src/console/` (task `10-27-daemon-console`, ADR 0003). The other files in this directory stay not-applicable.

## Console conventions

- No build step and no npm runtime dependency: Preact + hooks + htm are vendored under `src/console/vendor/` (versions, sources and sha256 in its `README.md`; `.gitattributes` keeps the `.mjs` files byte-exact; knip ignores `src/console/**`).
- CSP is `script-src 'self'; style-src 'self'`: no inline scripts, no import maps, no inline `style` attributes. `hooks.mjs` imports `./preact.mjs` relatively for this reason.
- `src/console/public/index.html` loads `/app/app.js` and `/app/styles.css`; `/app/redeem.js` is the only public script (link redemption page). `/app/styles.css` is also public; redemption/hint HTML uses the mobile viewport meta, external stylesheet and a `main` wrapper.
- API calls: same-origin `fetch`; every POST sends `Content-Type: application/json` and `X-PDD-Console: 1`. 401 means the console session expired — tell the user to ask for a new link.
- Secrets are write-only: password inputs use `autocomplete="new-password"`, are cleared after submit whether or not it succeeds, and saved values are never fetched or shown. `CredentialForm` is the only login-name/password form, shared by the account page (save password) and the account list (`+ 添加店铺` → `/api/accounts/add` → session page without slug). Add sits in a native `<details class="accordion">` open only when the list is empty; password expands under the detail page's password row (`修改密码`/`设置密码` toggle with `aria-expanded`/`aria-controls="password-form"`), open by default only when `status_kind` is `relogin_paused` (`AccountActions` is keyed by slug so switching shops resets it), and collapses after a successful save.
- Takeover shows only the captcha dialog: frames arrive over SSE (`event: frame`, `{ jpeg, width, height }` with `jpeg: null` while no dialog is found, shown as「等待验证码…」); pointer coordinates are normalised to 0–1 against the image's current rendered rect; the frame element uses `touch-action: none`. No full-page view, zoom or toolbar buttons.
- Takeover gestures: only the first finger (or mouse) is sampled as down/move/up; extra fingers are ignored. Each down creates a random `gesture_id`, timestamps relative to that down, and a zero-based batch `seq`. A 50ms flush starts sending; only one request is in flight, batches contain at most 200 events and one gesture, and backlog drains immediately after each response.
- Pointer failure or `result: interrupted` clears queued input and displays「拖动中断，请重新操作」; a fresh down retries with a new id. Transport failure also attempts `/pointer { gesture_id, seq, events: [], cancel: true }` to release the affected gesture; the server idle timeout covers failed cancellation. Unmount clears the local queue/timer and suppresses late focus/error updates. A 401 keeps the expired-link prompt.
- Account cards and the detail page show one `StatusBadge` (`status` + dot coloured by `status_kind`) and `status_detail`; buttons are chosen from `status_kind` / `has_password` only. Paused: primary `扫码登录`, secondary `恢复自动登录`; otherwise primary `重新登录` with a password, else `扫码登录`. The detail page is a grouped list (`.group` / `.group-row`, label left, actions right, secondary before primary): a 登录 row, a 密码 row (`已保存`/`未保存`, `清除密码` as a `.plain` text button, the password toggle), then `删除店铺` alone in `.danger-zone` below the group. Button colours: primary dark (`--primary`), secondary grey fill (`--fill`), `.danger` red tint; red marks destructive actions only. List cards add a quick button only for `relogin_paused` / `action_required` / `relogin_required`, placed beside (never inside) the card link. `删除店铺` asks for the shop name via `window.prompt`, posts `{ confirm_name }` to `/remove`, and navigates to the list on `removed: true`.
- The list page shows `PatrolSwitch` on the right of the title row (`.page-header`): a status pill (`.patrol-pill`, 26 px visual, 44 px hit area) reading 巡航中 / 自动巡航 opens a panel (`.patrol-panel`) with the native `<input type="checkbox" role="switch">` (`.switch`), the explanation and the last patrol time; outside pointerdown or Escape closes it. Data comes from `GET /api/patrol`, toggles post `{ enabled }`, errors go to the list page notice, and on failure the re-render restores the server state. No component library or CDN: the CSP stays `self`-only.
- `useAccountAction()` is the single action runner for list and detail: shared busy/disabled state and a synchronous ref guard, covering same-tick repeated clicks before the next render.
- User-visible copy avoids internal terms (熔断, 接管, 会话, 重登); the session page shows one state line plus at most one backend message.
- SMS challenge (session state `sms`) shows no picture: a numeric input (`inputmode="numeric"`, `autocomplete="one-time-code"`, 4–8 digits) posts `{ code }` to `/sms`; `result` `submitted` / `wrong_code` / `form_changed` maps to a fixed message, and `wrong_code` clears the input.
- Takeover keyboard: the pointer response carries `editable` / `numeric` (booleans after an `up`, else null). `editable: true` focuses a hidden `.ime` input (numeric → `inputmode="numeric"` + `autocomplete="one-time-code"`), `false` blurs it. The input always holds one sentinel character (`​`): typed text is forwarded via `/text`, a deleted sentinel becomes `Backspace`, Enter is sent from `keydown`; text is flushed on `compositionend`, never mid-composition. There is no manual keyboard button.
- Mobile first: tap targets ≥ 44 px, single column ≤ 720 px, light/dark via `prefers-color-scheme`. Success text uses `--success-fg` (light `#1a7f37`, dark `#3fb950`).
- Verify UI changes on a fixture daemon (`PDD_TEST_ADAPTER=fixture`, temp `PDD_DB_PATH`, `PDD_CONSOLE_PORT`) in a real browser; the API contract itself is covered by `test/e2e/console*.e2e.test.js`.
